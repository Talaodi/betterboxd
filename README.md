# Betterboxd - AI 影迷综合助手

本项目作为清华大学程序设计训练 (Rust) 课程的大作业开发, 目前处于 Demo 阶段, 开发过程使用 Opencode + GLM / Deepseek 辅助.

Betterboxd 是专为影迷开发的综合助手, 本身不仅是一个完善且成熟的记录工具, 还结合 AI 综合优化使用体验.

本项目使用 TMDB (The Movie Database) 作为数据库, 其规定 API Key 不得公开传播. 为了能够正常使用本项目请自行注册 API Key (免费快捷, 过程约 5 分钟). 注册方式见 [GENERATE_TMDB_API_KEY.md](./docs/GENERATE_TMDB_API_KEY.md).

## 为什么选择 Betterboxd

- **记录功能是完整的, 不是只有输入框**: Diary 侧有 日期, 评分, 影院, 票价, 三个固定维度 (地点/场景/同伴), 自由标签和 Markdown 随记, 同一部片的多次记录会按观看日期数出"第几刷". Review 侧有标题, Markdown 正文, 署名评分和可以手动调整的署名日期. List 侧支持名称/描述/是否排名, 排名直接用拖拽改, 不需要手动填序号. 它们都被同一个 Action 账本记着, 谁改了什么, 什么时候改的, 都有记录.

- **数据用工具查, AI 只负责表达**: 这个项目的设计里, 数据出口是 AI 的工具面 -- 观影记录, 影评全文, 想看与喜欢, 清单和成员, 已保存的统计项目, 历史对话, 甚至维度值池和标签历史, 都有对应的查询工具. 这意味着 AI 回答里出现的每一个数字, 都有工具返回作为来源. 你问"我去年最喜欢谁", 它不会凭印象说, 而是先去查. 想要核实, 追问一句它用的查询就能看到.

- **偏好是由画像计算的, 不在提示词里猜**: 每次对话, 系统会自动组装一份你的影迷画像 (总量, 类型偏好, 导演偏好, 同伴, 平均分, 最近记录) 注入到提示词里. 推荐类问题, 流程是 画像 -> 翻已有记录 -> 搜索候选 -> 排除看过的 -> 输出理由; 每一步都可以被追问.

- **统计不需要预置, 问法决定做法**: 项目里没有内置的统计报表. 你问什么, AI 在只读 SQL 视图上现场写查询, 计数, 均值, 排序, 窗口都可以. 碰到风格, 情感, 主题这类没法用 SQL 硬算的问题, 它会改成翻阅你的记录和影评, 逐条读完之后总结. 因为查询是走只读视图的, 最坏情况是问不出东西, 不可能改坏数据.

## 构建

构建流程目前仅保证在 Linux 系统 (包括 WSL2) 下适用, 若使用其他系统出现问题请反馈.

编译:

```bash
cd apps/web
npm install
npm run build              # 产物 apps/web/dist
cd ../..
cargo build                # 产物 target/debug/betterboxd-server
```

运行:

```bash
./target/debug/betterboxd-server        # 或 cargo run -p betterboxd-server
```

浏览器打开 http://localhost:3000.
